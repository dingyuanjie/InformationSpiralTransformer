# Level 6.14：动态轨迹因果分析

## 协议核验

- 3/3 个独立模型完成
- 每模型 4 个预注册槽位对
- 时间点：chunk 1、2、4、8、12、15 之后
- 干预：zero-once、zero-persistent、swap-once、keep-pair-persistent
- 每条件：3 个新评估种子，共 1,200 个配对样本
- 每条 pair × mode 时间族内执行 Holm 校正
- 完成 291 个条件，共 349,200 次样本级评估

## 核心结论

第三层槽位记忆在第一个 chunk 后已经携带样本特异信息，并持续参与直到最终读取。
系统对“信息缺失”高度容错，却对“内容错误但分布正常”的记忆极其敏感。槽位缺失
和槽位污染不是同一种干预。

## 1. 一次清零通常可以恢复

- seed 606：0/24 个 zero-once 时间点经 Holm 校正显著。
- seed 808：10/24 显著，但损失通常只有约 1–2 pp。
- seed 1001：5/24 显著，且方向混合。

因此单次删除一对槽位后，后续 chunk 的更新通常能重新写入或由其他槽位补偿。
恢复不是所有初始化都完美，但整体行为损失很小。

## 2. 一次跨样本交换在所有时间点都造成灾难性损失

swap-once 在 72/72 个模型 × 槽位对 × 时间点中全部经 Holm 校正显著：

- seed 606：损失约 30–37 pp；
- seed 808：损失约 35–44 pp；
- seed 1001：损失约 20–31 pp。

交换保持了槽位数值的边际分布，只破坏“该 Memory 属于哪个样本”的对应关系。
它远比置零危险，说明模型会主动读取并信任这些槽位。错误记忆不会像缺失记忆那样
触发有效补偿，反而会持续误导最终预测。

swap-after-1 已经造成巨大损失，说明样本特异信息在第一个 chunk 后就进入这些槽位；
swap-after-15 仍造成同量级甚至更大的损失，说明这些身份绑定一直保留到最终读取前。

## 3. 持续清零确认总体冗余，但存在初始化特异的维护窗口

### seed 606

大部分组合持续清零影响很小。例外是已确认脆弱对 (1,30)：

- after-1：损失 3.00 pp，95% CI [1.75, 4.33]，Holm p = 3.53e-5；
- after-2：损失 2.75 pp；
- after-4：损失 4.00 pp；
- after-8 以后：损失收缩到约 0.5 pp，不再显著。

因此 (1,30) 的破坏主要发生在早期积累/维持阶段，而不是最终读取阶段。晚期删除时，
其他槽位已经形成足够备份。

### seed 808

zero-persistent 仅 1/24 个时间点显著。即使持续删除已确认协同对，剩余槽位通常仍可
维持结果。这再次区分了“单独保留时有帮助”和“完整系统中不可替代”。

### seed 1001

zero-persistent 有 18/24 个时间点显著，但全部是性能改善：早期开始持续清零可提高约
2–3 pp，随后效应逐步衰减，并在 after-15 接近零。这确认了 Level 6.13.1 的推断：
seed 1001 含有早中期冗余干扰或过度写入，删除部分槽位具有正则化作用。

## 4. 只保留槽位对揭示推理期状态重组

keep-pair-persistent 的结果取决于何时开始裁剪，而不是只由最终槽位编号决定。

典型例子是 seed 1001 的 (2,7)：

- after-1：99.83%，比 intact 高 3.83 pp；
- after-2：99.83%；
- after-4：99.17%；
- after-8：94.42%；
- after-15：92.17%。

若从早期只留下两个槽位，后续 Memory 更新会把任务信息重分配到幸存槽位；若到
chunk 15 才裁剪，系统几乎没有时间重组。这是无参数更新情况下的状态动力学适应。

seed 606 的 (10,17) 也呈非单调轨迹：89.42% → 83.00% → 79.00% → 80.75%
→ 85.50% → 90.25%。中途裁剪最差，早期限制允许较长时间重组，晚期裁剪则保留了
其他槽位已完成的前期计算。

两个跨初始化通用对仍表现出很强充分性：

- (13,28)：所有模型、所有开始时间均为 90.83%–94.42%；
- (19,26)：多数时间为 91.25%–94.42%，仅 seed 1001 after-15 降至 88.75%。

所以 (13,28) 是目前最稳定的动态通用充分对。

## 5. 写入、维持、读取阶段定位

### 写入

第一个 chunk 后已经形成可被 swap 破坏的样本特异编码，因此关键写入不晚于 chunk 1。

### 维持

从 chunk 1 到 15，交换任意已确认槽位对都持续造成大损失，说明样本身份编码贯穿整个
上下文。清零影响小则表明该编码同时存在于其他槽位，可被重新写入或补偿。

### 读取

after-15 交换仍造成 26–43 pp 损失，证明最终 query 直接依赖倒数第二个 chunk 后的
第三层 Memory 内容。模型不是仅在早期读取一次后把信息永久转移到非 Memory 路径。

## 机制解释

当前最符合数据的模型是：

1. 第一个 chunk 将目标身份写入多个第三层槽位；
2. 后续 chunk 持续更新、复制和重组这些样本特异状态；
3. 槽位缺失会触发冗余补偿或重新分配；
4. 分布正常但属于另一条样本的槽位内容会被模型当成可信证据；
5. 最终 query 仍直接读取这些状态，因此晚期污染同样致命。

简写为：**缺失可恢复，污染会误导；编码早形成，身份持续到最终读取；槽位角色可在
推理期动态重组。**

## 下一步建议：Level 6.14.1 污染恢复动力学

下一步应聚焦 swap 的异常持久性，而不是扩大槽位组合：

1. 在 chunk 1、4、8、12 后交换槽位；
2. 在交换后的第 0、1、2、4 个 chunk 主动清零被污染槽位；
3. 比较“保持污染”“清除污染”“恢复正确槽位快照”；
4. 测量错误样本目标被预测的比例，而不只看总准确率；
5. 判断错误记忆是持续保留、被后续写入强化，还是通过门控阻止纠正。

这将直接解释为什么一次 swap 的影响可以跨越十多个 chunk，而一次 zero 几乎无害。
